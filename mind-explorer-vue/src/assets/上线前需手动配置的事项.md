## 一、Netlify 环境变量（必做区）

位置：**Netlify 后台 → 你的站点 → Deploys → Environment variables**（或 Site settings → Environment variables）。
新增后需重新部署（Deploys → Trigger deploy）才能生效。

> 注：实际部署的函数目录为 `netlify/functions/`（已在 `netlify.toml` 中配置 `functions = "netlify/functions"`）。顶层 `netlify/*.js` 是早期遗留副本，**不会**被部署，可忽略。
>
> 当前 `netlify/functions/` 实际在跑 8 个函数：`admin-review` / `auth-callback` / `auth-login` / `auth-logout` / `card-interactions` / `community` / `upload-content` / `user-points`。（**小木对话已不在这里**，见第二节。）

| # | 变量名 | 是否必填 | 代码默认值 | 不配的后果 | 去哪拿 |
|---|--------|----------|------------|------------|--------|
| 1 | `SUPABASE_SERVICE_ROLE_KEY` | **必填** | 空（无） | 心情日记、收藏、打卡、治愈瞬间投稿、社区/卡片互动 **全部降级** | Supabase 后台 → Project Settings → API → `service_role` 密钥（**仅服务端用，切勿泄露到前端**） |
| 2 | `GITHUB_CLIENT_ID` | **必填（若启用 GitHub 登录/轻账号）** | 无 | 「GitHub 登录」点了会跳到 `client_id=undefined` 的授权页，登录失败 | 注册 GitHub OAuth App 后获得（见第三节） |
| 3 | `GITHUB_CLIENT_SECRET` | **必填（同上）** | 无 | OAuth 回调换取 token 失败，登录不可用 | 同上，OAuth App 的 secret |
| 4 | `GITHUB_REPO_TOKEN` | **必填（若启用社区/积分/认同/评论/复习卡互动/旧投稿）** | 空（无） | 社区列表、贡献榜、认同/评论、复习卡片互动等 GitHub Issues 支撑功能读写为空或报错 | 生成一个有 `repo` 权限的 GitHub Personal Access Token（PAT） |
| 5 | `ADMIN_PWD` | **建议改** | `mind2024` | 不配则审核后台 `/admin` 用默认弱密码，存在被他人进入的风险 | 改成你自己的强密码，访问 `/admin` 时输入 |
| 6 | `DEEPSEEK_API_KEY` | 可选 | 空（无） | 每日陪伴语、每日文案、图片配文 **走内置模板**（仍可用，只是不够个性化） | DeepSeek 平台 → API Keys |
| 7 | `DEEPSEEK_BASE_URL` | 可选 | `https://api.deepseek.com/v1` | 一般无需改；仅当你用兼容代理/自建网关时改 | —— |
| 8 | `SUPABASE_URL` | 可选 | `https://bbdfeiceezcbcbsbnznr.supabase.co`（代码内置） | 一般无需配；仅当 Supabase 项目地址变化时改 | Supabase 项目 URL |
| 9 | `SUPABASE_ANON_KEY` | 可选 | 代码内置硬编码的 publishable key | sunny-push 在没有 service_role 时的回退；一般无需配 | Supabase `anon` 公钥 |
| 10 | `GITHUB_REPO_OWNER` | 可选 | `kangkang-del` | 仅当代码仓库不在该账户下时才改（否则社区/积分读写错仓库） | 你的 GitHub 用户名 |
| 11 | `GITHUB_REPO_NAME` | 可选 | `mind-explorer` | 同上 | 你的仓库名 |
| 12 | `DRY_RUN` | 调试用 | 不设 | sunny-push 调试开关，正式环境无需配 | —— |

## 二、Supabase Edge Functions 密钥（必做区）🆕

> 小木（companion）与内容中转（content）已从 Netlify Functions **迁到 Supabase Edge Functions**（Deno 运行时，新加坡区 `ap-southeast-1`）。
> 这两个函数**不在 Netlify 上**，因此上面的 Netlify 环境变量对它们**无效**——必须在 Supabase 后台单独配。

**位置**：Supabase Dashboard → **Edge Functions → Secrets**（Project Settings → Edge Functions 里也有入口）。
改完 Secrets 后 **必须重新 Deploy 对应函数**才生效（Edge Functions 是整包部署，没有热更新）。

| # | 变量名 | 是否必填 | 代码默认值 | 不配的后果 | 去哪拿 |
|---|--------|----------|------------|------------|--------|
| 1 | `HMAC_SECRET` | **必填（批次 M 新增）** | 空（无） | 后端身份校验**完全降级为旧行为**（不校验、不写日志、不产生 403）→ 越权访问仍可行 | 自己生成随机长串（≥32 字符），如 `openssl rand -hex 32` |
| 2 | `DEEPSEEK_API_KEY` | **必填** | 空（无） | **小木完全无法对话**（回退模板语录） | 当前实际填的是**智谱**的 API Key（变量名保留 DEEPSEEK_ 是历史原因） |
| 3 | `DEEPSEEK_BASE_URL` | **必填** | `https://api.deepseek.com/v1` | 不改成智谱网关则走不通 | 智谱网关地址，含 `bigmodel` 字样（代码据此自动启用 `glm-4-flash-250414` 兜底模型） |
| 4 | `LLM_MODEL` | **必填** | `deepseek-chat` | 模型名不对 → 调用报错 | 如 `glm-4-flash-250414` |
| 5 | `LLM_FALLBACK_MODEL` | 可选 | 自动：base url 含 `bigmodel` 时为 `glm-4-flash-250414` | 无 | —— |
| 6 | `LLM_BACKUP_BASE_URL` / `LLM_BACKUP_API_KEY` / `LLM_BACKUP_MODEL` | 可选 | 空（无） | 无备用通道（主通道限流时不做二次尝试） | 任意兼容 OpenAI 协议的服务 |
| 7 | `ADMIN_PWD` | 建议配 | 回退读 `app_config` 表 | 管理面（content 的管理 action）无法鉴权 | 与 Netlify 的 `ADMIN_PWD` 保持一致最省心 |

> ✅ **以下三个不用你配**：Supabase Edge Functions 会自动注入 `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`（平台默认 Secrets）。代码里读的 `SUPABASE_SERVICE_ROLE_KEY` 指的就是这个自动注入值。

### 2.1 函数的 JWT 开关（Dashboard 里逐个设置）

| 函数 | `verify_jwt` | 原因 |
|---|---|---|
| `companion` | **开启（ON）** | 只允许带 Supabase key 调用；不对公网裸奔 |
| `content` | **关闭（OFF）** | 它是「数据中转」，游客（未登录）也要能直接调用（如心情日记）。管理类 action 改由 `ADMIN_PWD` 把关 |

### 2.2 改完之后怎么自测（不用改代码）

| 探针 | 期望结果 |
|---|---|
| `POST companion` 不带任何 key | **401** `UNAUTHORIZED_NO_AUTH_HEADER` |
| `POST companion` 带公开 anon key + 伪造的 userId + 伪造 token | **403** `{"error":"身份校验失败",...}`（若返回 200，说明 `HMAC_SECRET` 没配或 `_shared/auth.js` 没生效） |
| `POST content`，body 为 `{"action":"auth.verify","userId":"g:g_test1","authToken":"x.y"}` | `{"ok":false,...}`（返回 500 说明新 action 还没部署上去） |
| `POST content`，body 为 `{"action":"随便乱写"}` | **400** `{"error":"无效的操作类型：…"}` |

## 三、GitHub Secrets（必做区，用于每日定时推送）

位置：**GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret**。

| 变量名 | 是否必填 | 不配的后果 | 说明 |
|--------|----------|------------|------|
| `SITE_URL` | 可选但建议 | 每日定时推送任务跳过（**非阻断**：前端「今日精选 / 心灵晴天」打开时会兜底懒触发，所以没配也能跑，只是无人访问时不会有预置内容） | 填部署后的站点地址，**不含末尾斜杠**，例如 `https://mind-explorer.netlify.app` |

> 配套文件：`.github/workflows/sunny-push.yml`（cron `0 0 * * *` UTC = 北京时间 08:00）。该 Actions 仅在仓库 **默认分支** 上运行，需确保仓库已启用 GitHub Actions。
> 另有 `.github/workflows/supabase-keepalive.yml`：仅用于保活 Supabase 项目，无需额外配置。

## 四、第三方平台手动操作（非环境变量）

### 4.1 注册 GitHub OAuth App（启用「轻账号 / GitHub 登录」必做）
1. 打开 **github.com → 右上角头像 → Settings → Developer settings → OAuth Apps → New OAuth App**。
2. **Application name**：心灵探索（或任意）。
3. **Homepage URL**：你的部署站点地址，例如 `https://mind-explorer.netlify.app`。
4. **Authorization callback URL**：`https://<你的站点>/.netlify/functions/auth-callback`（必须精确匹配，否则回调 404）。
5. 创建后得到 `Client ID` 与 `Client secret`，分别填入 Netlify 的 `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`。
6. 生成的 `GITHUB_REPO_TOKEN`（见上表第 4 项）建议给 `repo` scope，供社区/积分等功能读写 Issues。

> 若你 **不打算** 提供 GitHub 登录，可跳过 4.1，并把前端登录入口视为「访客（guest）模式」——访客模式不依赖任何密钥即可使用基础功能。

### 4.2 Supabase 数据库表（大部分已通过 MCP 迁移完成，**但有 1 张表需要你手工执行一次**）

以下表与 RLS 策略已执行 SQL 迁移（`sql/*.sql`），**RLS 启用但无开放 policy，所有读写经服务端中转**：
- `companion_messages`（小木对话记忆）
- `user_profiles`（轻量用户画像）
- `mood_diary`（心情日记）
- `user_cards`（治愈瞬间投稿）
- `user_favorites`（收藏）
- `user_checkins`（打卡）

#### 🆕 批次 N 需要你手工执行一次（跨设备同步，2026-09-24 新增）

打开 **Supabase Dashboard → SQL Editor**，把仓库里的
`mind-explorer-vue/sql/xiaomu_user_state.sql` **整段复制粘贴执行**（幂等，重复跑安全）。

它会做两件事：
1. 建表 `public.xiaomu_user_state`（`user_identifier` 主键 + `version` 乐观锁 + `payload jsonb`），并 `ENABLE ROW LEVEL SECURITY`（**故意不建 policy** → 只有 service_role 能读写，与 `mood_diary` 同策略）。
2. 建 **私有** Storage 桶 `xiaomu-skins`（`public=false`、单文件上限 1MB、只允许 `webp/png/jpeg`）—— 用于跨设备同步自定义形象图片。

> ⚠️ **必须跑，且要在部署 `content` 函数之前跑**：
> - 漏建表 → `state.get/put/putSkin/clearSkin` 四个 action 全部 500，**跨设备同步整体失效**（前端会静默降级为「纯本地」，桌宠本身照常可用，所以不易察觉）。
> - 漏建桶 → 表格数据（换装/天数/解锁）能同步，只有**自定义形象图片**上传失败，前端提示「形象图片同步失败（本机仍然可用）」。

> 你另外要做的就是把我给你的 **Supabase `service_role` 密钥**分别填进 **Netlify 环境变量**（第一节第 1 项）——Edge Functions 那边平台自动注入，不用管。
> 社区帖子 / 积分 / 认同评论等走 **GitHub Issues** 通道，由 `GITHUB_REPO_TOKEN` 支撑，与 Supabase 无关。

## 五、按功能模块对照：哪些没配会怎样

| 功能模块 | 关键依赖 | 未配置时的表现 |
|----------|----------|----------------|
| 小木对话（多轮 + 记忆） | **Edge** `DEEPSEEK_API_KEY` + `DEEPSEEK_BASE_URL` + `LLM_MODEL` | 无 key → 模板语录（仍流式） |
| 小木身份校验 / 防越权（批次 M） | **Edge** `HMAC_SECRET` | 无 → 降级为旧行为，不校验（功能不缺，只是越权仍可行） |
| 小木跨设备同步（批次 N） | **SQL Editor 执行** `sql/xiaomu_user_state.sql`（建表 + 建桶） | 未建表 → `state.*` 全 500、同步整体失效（静默降级纯本地）；未建桶 → 仅形象图片上传失败 |
| 每日主动陪伴语 | **Edge** `DEEPSEEK_API_KEY` + 自动注入的 `SUPABASE_SERVICE_ROLE_KEY` | 无 → 通用暖语；服务端存储缺失 → 不落库 |
| 心情日记 + 情绪曲线 | **Edge** `SUPABASE_*`（自动注入） | 无（异常情况）→ 保存/读取返回「未启用存储」 |
| 收藏（四类） | Netlify `SUPABASE_SERVICE_ROLE_KEY` | 无 → 收藏按钮无效 |
| 打卡 / 连续天数 | Netlify `SUPABASE_SERVICE_ROLE_KEY` | 无 → 打卡静默跳过 |
| 治愈瞬间投稿 + 审核 | Netlify `SUPABASE_SERVICE_ROLE_KEY` + `ADMIN_PWD` | 无 service_role → 投稿失败；默认密码 `mind2024`（建议改） |
| 社区交流 / 认同 / 评论 | `GITHUB_REPO_TOKEN` | 无 token → 列表可能为空或仅极少量公开数据 |
| 贡献榜 / 积分 | `GITHUB_REPO_TOKEN` | 无 token → 拉取失败 |
| GitHub 登录 / 轻账号 | Netlify `GITHUB_CLIENT_ID` + `GITHUB_CLIENT_SECRET` + OAuth App | 未注册/未填 → 登录失败；可用 guest 模式替代 |
| 每日自动推送（心灵晴天） | `SITE_URL`（GitHub Secret） | 未配 → 定时任务跳过，前端兜底触发仍可用 |
| 自助工具箱 / 危机文案 | 无外部依赖 | 纯前端，始终可用 |

## 七、最小可上线清单（不折腾版）

只想要网站先跑起来？按这个顺序配 **6 项** 即可：

1. **Edge** `DEEPSEEK_API_KEY` + `DEEPSEEK_BASE_URL` + `LLM_MODEL` ← 让小木能说话（当前接的是智谱）
2. **SQL Editor** 执行 `sql/xiaomu_user_state.sql` ← 跨设备同步的地基（**批次 N，必做**）
3. **Edge** `HMAC_SECRET` ← 打开身份校验，堵越权（批次 M）
4. Netlify `SUPABASE_SERVICE_ROLE_KEY` ← 让收藏/打卡/投稿/社区可用
5. Netlify `ADMIN_PWD` ← 改成自己的密码（不然审核后台用默认弱密码）
6. （可选）GitHub Secret `SITE_URL` ← 开启每日自动推送

其余（`LLM_BACKUP_*`、`GITHUB_CLIENT_ID/SECRET/TOKEN`）均为「配了更好、不配也能用（降级）」的可选增强。
